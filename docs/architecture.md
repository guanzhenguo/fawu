# 架构与领域边界

## 部署视图

```text
Vue 3 工作台
      │ Token / future OIDC
      ▼
Django REST API ─────────────── MySQL 8.4
  ├─ template                     ├─ 业务事实
  ├─ contract                     ├─ 审批流水
  ├─ review                       └─ 加密映射（未来）
  ├─ approval
  └─ audit ───── Celery ─────── Redis / RabbitMQ
                     │
                     ▼
             FastAPI Document Gateway ─── OSS/S3
                ├─ DOCX 安全解析
                ├─ 高保真 Diff 适配器
                ├─ 脱敏与还原适配器
                └─ 外部 AI 适配器
```

核心业务采用模块化单体，文档和 AI 网关独立部署。合同审批需要本地事务和统一审计，不在首期拆成多个数据库；文档解析属于高 CPU/高风险输入，独立扩缩容并限制网络权限。

## 核心不变量

1. 模板发布生成基线指纹，历史合同始终关联签约时的模板版本。
2. 已定稿合同版本不可修改；修改必须创建新版本。
3. 审批动作和审计事件只追加，不提供更新、删除接口。
4. 路由由版本化确定性规则决定，AI 发现只能增加风险，不能直接自动放行。
5. 高风险流程只有全部会签任务通过才完成；任一驳回即取消其他待办。
6. 外部模型只能接收经过最小化和脱敏的数据。

## 合同快照格式

```json
{
  "variables": {
    "contract_amount": "100000.00"
  },
  "clauses": [
    {
      "code": "PAYMENT",
      "content": "乙方应在验收合格后十个工作日内支付全部价款。"
    }
  ]
}
```

`code` 是条款的稳定业务标识。风险引擎使用规范化文本哈希判断确定性偏离；高保真 Word 修订结果和语义偏离结果未来作为 `RiskFinding` 写入同一个审查实例。

## 工作流演进

当前需求只有固定的三级风险路线，因此使用版本化审批表实现，便于测试和审计。如果出现可视化流程编排、多级条件网关、流程迁移或大量子流程，再以适配器方式接入 Flowable；合同、审查和审计模型无需替换。
